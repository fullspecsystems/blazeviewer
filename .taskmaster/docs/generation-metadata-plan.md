## The feature in one paragraph

An image generated by ComfyUI or an Automatic1111-family WebUI carries the whole
recipe in its metadata. Today Blaze Viewer reads **none** of it. Add a
**Generation** section at the top of the Inspector ▸ Details table — prompts,
model, seed, steps, CFG, sampler — and two clipboard commands for the full
payload. **Every fact is emitted only when it is unambiguous**; anything the
graph does not state literally is reported as unknown, never guessed. The raw
JSON is never dumped inline.

## What is actually in the files (measured)

Each of the three sample PNGs carries exactly two **uncompressed `tEXt` chunks,
ahead of `IDAT`**, and **zero EXIF**:

| keyword | size | what it is |
|---|---|---|
| `prompt` | ~4.4 KB | the **API graph** — the graph that actually executed |
| `workflow` | ~24 KB | the **UI graph** — positions, groups, link table, **and nodes that did not run** |

The API graph is `{ "<node_id>": { "class_type": str, "_meta": {...}, "inputs":
{ name: literal | [src_node_id, slot] } } }`. Measured facts from the sample:

```
checkpoint   lustifySDXLNSFW_oltFIXEDTEXTURES.safetensors
sampler #3   35 steps, cfg 6.0, dpmpp_2m_sde / karras, denoise 1.0
seed         98767            (literal on an `easy seed` node, LINKED into the sampler)
latent       832 × 1216
refine #202  30 steps, cfg 5.5, denoise 0.31
positive     ⚠ NOT a literal — node 6's `text` is linked from a PromptCombinator
```

## Why nothing shows today

The Details panel is **not** empty — it shows dimensions, codec, file size and
animation facts (`app_core_impl/meta.rs:73`, `:93`, `:109`). What is missing is
generation metadata specifically, blocked by three layers:

1. **`pb-decode` never reads PNG text chunks.** Grepping the tree for
   `tEXt|iTXt|zTXt` returns **zero hits**; `read_exif_fields`
   (`pb-decode/src/metadata.rs:10`) is the only metadata reader.
2. **`is_exif_blob` (`engine.rs:1093`) drops any value over 256 *bytes*** —
   `value.len()`, not chars. Both chunks would vanish silently.
3. **`EXIF_VALUE_MAX = 72` (`engine.rs:334`)** via `truncate_exif_value`
   (`engine.rs:1099`), which *does* count chars. A prompt would be a 72-char stub.

## Threading — stated honestly, not rationalized away

`ensure_exif_cached` (`app_core_impl/meta.rs:153`) calls `source.bytes(item)`
**synchronously on the event loop** (`meta.rs:213`). That is a **pre-existing
violation**, not a licence for more: `ItemSource::bytes` documents itself as
"Called off the event loop, on decode-pool worker threads"
(`pb-source/src/lib.rs:116-119`), `FsSource::bytes` is a plain `fs::read`
(`lib.rs:295`), and the charter says never block the event loop.

**rev-1 was wrong** to argue "the read is already paid for, so parsing is free."
Two corrections:

- The bytes are **not** already in memory. `ensure_exif_cached` re-reads the file;
  it does not reuse decode-pool buffers.
- The call scope is wider than Details. `ensure_exif_cached` is also reached from
  AI describe (`describe.rs:197`), subtitles (`subtitles.rs:39`, `:122`, `:205`),
  audio tracks (`audio_tracks.rs:40`, `:157`) and video open (`video.rs:694`).
  Work added inside it runs on all of those.

**Decision:** land the extraction on the existing synchronous path — it is where
EXIF already lives, and the added work is bounded (see budgets below) — and record
the debt rather than deny it. **Moving still-image Details extraction to a
cancellable background job is filed as its own task**, using the machinery the
video path already has (`media_details::spawn` with deck-generation + item-identity
checks, `meta.rs:182`). Doing it inside this task would refactor a path with six
callers and balloon the scope.

**Budgets that make the sync cost bounded and stated:**

| step | cap |
|---|---|
| chunk-header walk | linear, `IDAT` payloads skipped by length |
| keywords collected | **only** `prompt`, `workflow`, `parameters` — nothing else is retained |
| per-chunk inflate | 1 MB, **discard the chunk** on overflow (never truncate) |
| JSON parse | only `prompt`; `workflow` is never parsed |
| graph size | 4,096 nodes; larger → no facts |

A `PB_PERF` episode wraps Inspector-open so the cost is measured rather than
asserted. rev-1's "microseconds" claim was unmeasured and is withdrawn.

## The correctness trap: parse `prompt`, never `workflow`

The sample proves it. `workflow` contains node 88, a `CLIPTextEncode` holding a
plausible literal positive prompt, with **`"mode": 4`** (NEVER / muted). It is
**absent from `prompt`**: it did not run. A reader that scans `workflow` for
`CLIPTextEncode` nodes — what most third-party tools do — reports a prompt that
did not make this image.

`workflow` is the **copy payload only**. `prompt` is the source of facts.

## The safety invariant, and how it is actually enforced

> **A fact is emitted only when every viable candidate agrees. Otherwise it is
> omitted and reported as unknown.**

rev-1 claimed "found structurally or omitted, never wrong" but used greedy
first-match traversal, which breaks the claim in at least five ways (Codex
review, §2). Each is now closed by an *agreement* rule rather than a heuristic:

| Break | rev-1 (unsafe) | rev-2 rule |
|---|---|---|
| Several `SaveImage` nodes | "first by node id" — ids are not output order | Collect all. Facts are emitted only where **every** save-node's ancestry agrees; disagreement → omit. |
| No `SaveImage` | pick an arbitrary unconsumed sink | **No terminal → no facts.** Copy payload still offered. |
| The graph is a DAG, not a path | single-path walk could follow a mask/reference layer | Traverse **all** image-like inputs (BFS with visited set). Ambiguity is then visible instead of hidden. |
| "any node with `steps` is a sampler" | detailers, upscalers, restorers expose `steps` | A sampler must have **`positive` + `negative` + `latent_image`** inputs — the actual sampler contract. `steps` alone proves nothing. |
| "deepest sampler = base" | false for img2img / inpaint, where the deepest pass only builds an *input* | Headline numbers only when the ancestry yields a **unique** deepest sampler. Otherwise every pass is listed unlabelled, with no "base". |

**Prompt resolution is cut entirely** (Codex "things to cut", accepted). Hopping
links and taking "any string literal" can grab a delimiter, a filename prefix, a
style name, or one arbitrary combinator alternative — and then label it
`Resolved`, which is the worst outcome available. So:

- `text` is a **literal** → report it.
- `text` is a **link** → `Unresolved { via: <source class_type> }`, **no text**,
  and the panel says so: *"not stored literally — assembled by PromptCombinator"*.
  Copy Generation Prompt refuses with that reason.

For the owner's own samples this means the positive prompt shows as unresolved.
That is the truth: the string that made this image is not in the file.

**Linked scalars get exactly one narrow rule** (Codex §2.7 — rev-1 left them
unspecified while the sample's seed *is* linked). A linked scalar resolves only
when the source node carries a literal under the **same input name**
(`seed` ← a node with a `seed` literal). Any other shape → unknown. This covers
the ubiquitous seed-node case without guessing.

**Model and LoRAs:** walk the `model` chain. If any node on it has **two or more
`model` inputs** (a merge), stop and omit the model — do not pick a side. LoRAs
are collected only along an unforked chain.

**Latent size:** only from a node carrying literal `width` **and** `height` and
having **no** image-like input (i.e. a genuine chain head). A crop or upscale
node's `width` is not the latent size.

## Why this is still not a rabbit hole

The traversal keys on **input names**, never `class_type`. Verified on the sample:

```
133 SaveImage
  200 VAEDecode
    202 KSampler   steps=30 cfg=5.5 denoise=0.31
      201 VAEEncode
        199 CR Upscale Image          <- third-party custom node
          8 VAEDecode
            3 KSampler   steps=35 cfg=6.0 denoise=1.0
              5 EmptyLatentImage
```

It crossed `CR Upscale Image`, from a pack we know nothing about, because the
input name `image` is conventional. This graph uses seven custom packs and the
walk ignores all of them.

**What is stable:** the API-graph format is ComfyUI's HTTP `/prompt` payload,
unchanged since 2023 — it cannot change without breaking every saved workflow.
The core input names (`positive`/`negative`/`latent_image`/`model`/`text`/
`ckpt_name`/`lora_name`/`images`) are equally frozen, and custom nodes copy them.
**What is unstable is the node universe** — so we never enumerate it.

## Where to draw the line

| Row | Emitted when |
|---|---|
| Positive / Negative prompt | the sampler's conditioning node has a **literal** `text` |
| Model | the `model` chain is unforked and ends in a `ckpt_name`/`unet_name` literal |
| LoRAs | collected along that same unforked chain |
| Seed · Steps · CFG · Sampler/Scheduler | a **unique** deepest sampler exists; scalars literal or name-matched one hop |
| Latent size | a genuine chain head carries literal `width` + `height` |
| Pass *n* | one line per additional sampler, ancestry-ordered |
| Tool | detected from the keywords present |

**Everything else → the clipboard.** No upscaler settings, no VAE node, no node
titles, no positions. The hard stop is the anti-rabbit-hole mechanism.

## The A1111 family

One flat `tEXt` string under keyword `parameters`:

```
<positive prompt>
Negative prompt: <negative>
Steps: 20, Sampler: DPM++ 2M, CFG scale: 7, Seed: 12345, Size: 512x768, Model: sd_xl_base
```

**Naive parsing is not safe** (Codex §2.9): a prompt can itself contain a line
starting `Negative prompt:` or `Steps:`, and parameter *values* contain commas
(`Lora hashes: "a: 1, b: 2"`). Rules:

1. The parameter record is the **last** line of the payload, and only counts as
   one if it starts with a **known key** (`Steps:`/`Sampler:`/`Seed:`/`CFG scale:`).
   No such line → the whole payload is the positive prompt, no params.
2. Split the record on `, ` **only at a `Key: ` boundary** (`, ` followed by a
   token matching `[A-Za-z][A-Za-z0-9 ]*: `), not on every comma.
3. Split prompts at the **last** `\nNegative prompt: ` above the record.

**EXIF `UserComment` needs work in `pb-decode`, not `genmeta`** (Codex §2.10 —
rev-1 called this "nearly free", which was wrong). `field_value`
(`pb-decode/src/metadata.rs:27`) only byte-decodes `Value::Ascii`; an
`Undefined` value like `UserComment` goes through `display_value()` and reaches
the caller already mangled into escapes. So add
`read_exif_user_comment(bytes) -> Option<String>` in `pb-decode`, decoding the
8-byte charset prefix (`ASCII\0\0\0` / `UNICODE\0` / `JIS`/undefined) and UTF-16
by BOM, **while the raw field bytes still exist**.

⚠ **No verified A1111 sample is on hand** (owner, 2026-08-04). This arm ships
against hand-authored fixtures and is **not claimed as working** until a real PNG
*and* a real EXIF JPEG/WebP are checked.

## Architecture

### L1 — `pb-decode/src/png_text.rs` (new)

```rust
pub fn read_png_text(bytes: &[u8]) -> Vec<(String, String)>;
```

- Walk to `IEND` (chunks may legally follow `IDAT`), skipping `IDAT` by length.
- **Validate the CRC** of any chunk whose payload is collected; a bad CRC drops
  that chunk (Codex §2.11 — a corrupt A1111 block must not parse into wrong facts).
- **Collect only** `prompt`, `workflow`, `parameters`. Everything else is skipped
  without allocating — this replaces rev-1's generic "every text chunk, 8 MB" API.
- **Duplicate keyword → ambiguous**: drop both, do not first/last-wins.
- Inflate capped at 1 MB; overflow **discards the chunk atomically**.
- Truncated / malformed / non-PNG → return what was validated. Never panic.
- ⚠ **Does not ride `catch_panics`** (Codex §1) — that wrapper is private and typed
  to `Result<DecodedImage, DecodeError>` (`pb-decode/src/lib.rs:813`). This
  function is called directly and must be panic-free on its own merits, which is
  why it gets a fuzz target.
- `flate2` is already a `pb-decode` dep (`Cargo.toml:35`).

### L2 — `pb-app-core/src/genmeta.rs` (new; pure, no I/O)

`serde_json` is already a `pb-app-core` dep (`Cargo.toml:55`).

```rust
pub enum GenTool { ComfyUI, Automatic1111 }        // no Unknown — absence is `None`

pub enum PromptSource { Literal, Unresolved { via: String } }
pub struct PromptText { pub text: Option<String>, pub source: PromptSource }

pub struct GenerationMeta {
    pub tool: GenTool,
    pub positive: Option<PromptText>,
    pub negative: Option<PromptText>,
    pub model: Option<String>,
    pub loras: Vec<(String, String)>,
    pub params: Vec<(String, String)>,
    pub passes: Vec<String>,
    /// A payload exists (Copy is offered) even when no fact could be derived.
    pub has_payload: bool,
}

pub fn parse(chunks: &[(String, String)], user_comment: Option<&str>)
    -> Option<GenerationMeta>;
```

Detection: a `prompt` key → ComfyUI (**`workflow` is not required** — rev-1
demanded both, contradicting its own prompt-only copy path, Codex §2.12); a
`parameters` key or an A1111-shaped `UserComment` → A1111. Neither → `None`.
`has_payload` covers "workflow present, facts absent".

**Storage budget** (Codex §2.14): each prompt is stored capped at **16 KB**, and
the raw payloads are **not** retained — Copy re-reads the file. Worst case per
item is tens of KB, typical is under 1 KB. (`exif_cache` being unbudgeted overall
is pre-existing debt; filed as a follow-up, not fixed here.)

## Details that bite

- **`ItemDetails` gains `gen: Option<GenerationMeta>`** — every constructor answers
  explicitly. rev-1's inventory was short; the real set is `ItemDetails::ready` /
  `loading`, the archive arm (`meta.rs:204`), **`video.rs:259`** and
  **`media_details.rs:297`** (both missed in rev-1), plus test literals. Doors and
  videos answer `None`, per the crate's "a new kind opts out, not in" rule.
- **Archive entries work for free** — `source.bytes(item)` is source-agnostic, so a
  ComfyUI PNG inside a `.zip` gets its section. Needs a test, not code.
- **`_meta.title` is user-editable** and often an emoji nickname. Never a fact;
  `class_type` is the machine name.
- **Node ids are JSON strings** (`"3"`), not numbers. Compare as strings.
- **Cycles and depth.** A malformed graph must terminate: visited set + depth cap.
- **`prompt` absent, `workflow` present** → `has_payload: true`, no facts, Copy
  offered. Never read `workflow` for facts.

## Privacy

- Read-only, RAM-only, on-demand — same category as the existing EXIF read
  (`meta.rs:150`). Nothing written; `GenerationMeta` dies with the process.
- Re-run the no-trace test (`viewing_a_folder_writes_nothing_to_disk`) and the
  static `fs::write`/`File::create` audit. This adds no passive write path.
- ⛔ **Generation prompts must NOT enter the AI-describe context.**

2. **`DetailRow::Note` loses its italics on macOS** — mapped to `kind: 1`, an
   ordinary pair. Cosmetic only; the wording still reads correctly. Fix is a new
   kind rendered italic + secondary.
3. **`DetailRow::Body` rendering is unverified on macOS.** It maps to `kind: 2`,
   which `InspectorPanel.swift:249`'s `default:` arm already renders, and Details
   is tab 0 so it takes the literal `Text` branch rather than
   `MarkdownBlocksView` — read from Windows, **never run**. Confirm a prompt
   paragraph renders and wraps.
4. **The Mac Edit menu does not offer the two commands.** Both are wired in
   `pb-app`'s muda menus only; the Mac host needs its own entries. Dispatch is
   generic (`menuAction("copy_gen_prompt")` / `"copy_gen_data"`), so no bespoke
   FFI method is required.

None of the above breaks the Mac build: every FFI change was a match arm using
field access, never a struct literal, and `ContextMenuState` gained no field in
the end (the context-menu items were dropped by owner decision, which removed
that debt entirely).

**Decisions (owner, in session)**

- **File Size sits above the Generation block** — it is an identity fact beside
  dimensions and codec, and that group should not be split.
- **The copy commands are buttons on the Generation heading, not context-menu
  items.** They act on that section, and a context menu listing them for every
  photo would offer two commands that fail on almost all of them. This also
  deleted the `ContextMenuState.has_generation` field and the forced metadata
  read on right-click that answering it required.
- **Copy prompt appears only when a literal prompt exists** — a button whose only
  outcome is a refusal toast is worse than no button, with the reason already on
  screen beneath it.
- **The payload button names the real format**: *Copy JSON* for ComfyUI, *Copy
  parameters* for Automatic1111, whose block is not JSON.
- **"Assembled by X"** — no "not stored literally" preamble, sentence-cased,
  italic.
