## 0. What this fixes, and what it does NOT

**Fixes (the owner's felt pain, 2026-07-18):** after a fullscreen `[f]` toggle, *advancing* to a
neighbour shows its ~256px embedded preview for a couple seconds before the sharp version arrives.
Root: on any geometry change the ring is thrown away **whole — Originals included** — so a neighbour
has no high-res copy to fall back on, and its Fit re-decodes from scratch.

**Does NOT fix (separate tracks, don't conflate):**
- The *current* photo's "fuzzy for ~1s then sharpens" on toggle — that's box-mip-vs-Lanczos, fixed
  by **task #110** (GPU-derived Lanczos from the retained Original). #110 is independent of this
  work and lower-risk; it operates on the current photo's *already-retained* Original.
- The Windows/RDP present behaviour and the (already-fixed) stuck-preview desync (#111,
  `decode_is_definitive_full`, commit `327c3d0d`).

## 1. The one correction that reframes the whole draft

Rachel's draft (and the parent plan's §2) imply the parked full-res **Original survives a geometry
change** and item-6 just needs to *re-present* it. **On the current tree that is false.**

`invalidate_geometry` does `self.ring = ResidentRing::new_with_budget(cap, RING_BUDGET_BYTES)` — a
**brand-new ring**. That discards **every** slot, `Original` included. The renderer's `reserve_ring`
likewise empties its GPU slot vector, stashing only the *presented* slot into `held`.

So today **exactly one** texture survives a toggle: the current photo's, and only because `resize()`
presents its Original *before* the 180ms settle fires `invalidate_geometry`, so the renderer captures
it in `held`. Every neighbour's Original is gone. That is *why* advancing lands on a re-decoded
preview, and it's why this task is genuinely **retain-the-ring**, not merely "re-present what's
already there."

**Consequence for scope:** item-6 must make `invalidate_geometry` *keep* the resident Originals (and
remap them on the renderer) instead of newing up an empty ring — and then a **display-selection rule**
must let the **navigation** path (not just resize) present a neighbour's retained Original.

## 2. Verified current state (ground truth)

**Already built (unused outside `pb-core` tests):**
- `ResidentRing::drop_fit_slots() -> Vec<(item, old_slot)>` — frees stale `Fit` slots, keeps
  resident `Original`s, clears the `displayed` pin. Tested (`drop_fit_slots_keeps_originals…`).
- `ResidentRing::compact_to(new_capacity, keep: &[usize]) -> Vec<SlotRemap>` — compact survivors in
  priority order into the new (possibly smaller) ring; drop occupants over budget/capacity. Call
  **after** `drop_fit_slots`.
- `SlotRemap { from, to, item }`.
- The parked full-res tier: `full_res_window(radius)` / `full_res_radius()` (default 1) decode +
  hold Originals for `current → compare-pin → neighbours`, gated on `held_nav().is_none()`.
- `content_gen` is separate from the geometry `epoch`; `Representation::Fit{geometry_epoch}` vs
  `Representation::Original` (geometry-independent).

**Missing (the gap):**
1. `invalidate_geometry` **discards** the ring (§1) instead of `drop_fit_slots` + `compact_to`.
2. The `Renderer` trait has **no `remap_ring`** — only `reserve_ring` (empties, stashes `held`) and
   `present_slot`.
3. No **display-selection rule** that a `Fit` display may be satisfied by a resident `Original`
   (`display_slot` = `slot_for_rep(item, RepKind::Fit)` only). So even a retained Original is invisible
   to the nav/display path.
4. `pb-render` does **not** depend on `pb-core` (needed to import `SlotRemap`).

**Existing behaviour this MUST integrate with (not duplicate):**
- `resize()` already presents the current photo's Original and arms `resize_hold` **before** the
  settle. With retain, the Original now survives *in the ring*, so this path must become "present the
  retained ring slot," not "present-then-rely-on-`held`." Do **not** add a second re-present mechanism
  (Codex).
- The stuck-preview fix: `request_prefetch`'s `preview_resident.retain(slot exists)` stays consistent
  after `drop_fit_slots` (it drops bookkeeping for the dropped Fits). Keep it that way.

## 3. Design

### Part A — `Renderer::remap_ring` (with the `held` fallback)

Add next to `reserve_ring`:

```rust
/// Rebuild the GPU slot vector to `new_capacity`, RELOCATING retained textures per `remaps`
/// (old→new slot) instead of dropping them. If `keep_presented` is Some(old_slot) and that slot
/// is NOT among the remaps (i.e. it won't be re-presented from the new ring), move it into `held`
/// and sync img_w/img_h — preserving today's blurry-but-present fallback. Returns which `to`
/// indices actually received a texture, so the caller can detect a partial remap.
fn remap_ring(&mut self, new_capacity: usize, remaps: &[SlotRemap], keep_presented: Option<usize>) -> Vec<usize>;
```

`gpu.rs` impl notes (model on `reserve_ring`):
- `let mut old = std::mem::take(&mut self.ring); let mut next = vec![None; new_capacity];`
- For each remap: **validate `r.to < new_capacity` in release** (not just `debug_assert!`) and reject
  duplicate `to`; `next[r.to] = old.get_mut(r.from).and_then(Option::take)`.
- **P0 (held fallback):** if `keep_presented` is Some(s) and `s` was not moved, take `old[s]` into
  `self.held` and sync `img_w/img_h` (exactly as `reserve_ring` does) so a no-retained-hit toggle
  still shows the old frame instead of blank. Only clear `held` when a retained slot is actually
  re-presented (Part D).
- `old` (dropped) may hold **lower-priority Originals** compaction discarded, not just Fits — the
  draft's "only Fits" comment is wrong.
- `self.present_idx = None`; caller re-selects via `present_slot`.
- Add `pb-core` to `pb-render/Cargo.toml` (`SlotRemap` re-exported from `pb_core`; no cycle).

### Part B — split geometry-retain from content-purge (P0 content_gen)

The load-bearing correctness rule: **retain iff `content_gen` unchanged.**

- **`invalidate_geometry` (retain):** bump `epoch` only; `drop_fit_slots()`; compute the new `cap`;
  `compact_to(cap, &keep)` where `keep = full_res_window(full_res_radius())` (current → compare-pin →
  neighbours — reuse it, don't hand-roll); `renderer.remap_ring(cap, &remaps, keep_presented)`;
  recompute `ahead`/`behind`; `pending_uploads.clear()`; then Part D re-present. **Pending Originals:**
  `compact_to` keeps only *resident* Originals and the decode pool cancels on epoch change — so
  explicitly re-request the still-wanted Originals via the normal `request_prefetch` after remap
  (state this; don't rely on the draft's silent assumption).
- **`invalidate_content` (purge):** bump `content_gen` **and fully reset the ring** (the current
  `new_with_budget` discard + `reserve_ring`) — must NOT call the retaining `invalidate_geometry`, or a
  stale Original crosses the content change ("wrong deck item N", the sharpest Codex-review bug). Add
  an explicit code comment stating the invariant.
- **Pre-existing hole to close first:** undo-rotation only `invalidate_content()`s when the photo is
  *displayed* (`undo`/`save_rotation` paths). Once Originals live longer, a navigated-away neighbour's
  Original can retain the old orientation. Fix: any pixel-affecting edit bumps `content_gen` /
  purges the affected item's residency regardless of what's displayed.

### Part C — display-selection rule (P0 scheduler) — *this is the owner's fix*

A `Fit`-mode display may be satisfied by a resident `Original` (GPU-refits it to the viewport). This
is what makes a **retained neighbour Original** actually show on **navigation** instead of the preview.

- Add `display_or_original_slot(item) -> Option<(slot, SatisfiedBy)>`: prefer the `Fit` slot; else the
  `Original` slot. Use it on the **nav/advance present path** (mirror the resize path, but for the
  cursor move) so advancing to a photo whose Fit was dropped but whose Original was retained presents
  the Original immediately.
- **The scheduler must agree, or it hangs/re-decodes:** `request_prefetch`'s job loop (`resident &&
  !is_prev → continue`), `work_pending`, and `target_caught_up` currently key on the **Fit** slot only.
  A Fit satisfied-by-Original must (a) NOT be treated as "still missing" (else `work_pending` spins and
  the pie shows over a sharp Original — `tick_pie` watches `sharpen_now()`), and (b) still schedule a
  **background Fit refine** (Part E) so quality reaches Lanczos. Introduce a `SatisfiedBy::Original`
  state distinct from "resident Fit" and "preview" — the "currently-presented representation" state
  Codex called for; it also disambiguates the stuck-preview conflation (an Original-satisfied display
  is NOT blurry, so `sharpen_now`/the pie must not claim it is).

### Part D — anti-hang re-present (result-checked)

`present_retained_or_fall_through()` after remap:
- Operate on **`target_item`** (Rachel's `self.item` doesn't exist). Present via
  `display_or_original_slot(target)`; **check the `present_slot()` bool**; only on success set
  `presented_epoch = Some(self.epoch)` (→ `target_caught_up`), restore the ring `displayed` pin
  (`ring.set_displayed(slot)`), update `displayed_item`/metadata, and `draw()`.
- On a miss (no retained hit / rebind fails): leave `presented_epoch = None`, keep the old frame (the
  `held` fallback from Part A), and let the normal async Fit decode fill in — **today's behaviour, for
  that one toggle**. Never a third state where a slot is retained but nothing presents it.
- No `drain_results` thread race (both serial on the event loop) — so this is *not* the reverted
  cff70ca0 hang. The danger is **logical**: a false success stamping the wrong frame resolved. Align
  with the tracked `present_item` result-propagation follow-up rather than adding a second unchecked
  present path.

### Part E — quality refinement (the (a)/(b) fork, resolved)

Ship **(b)** — present the retained Original refit **now**, and schedule a background refine — **but
current-item-only and silent** (Codex): do NOT present its embedded preview over the Original, and do
NOT show a pie over an already-sharp frame. The refine's endpoint should become **#110** (GPU-derive
the exact-size Lanczos from the retained Original — no SMB re-read, no CPU decode). Until #110 lands,
the refine is the existing CPU-Lanczos Fit decode, presented only when it's a genuine quality upgrade
over the Original refit. **(a)** (Original-only, no refine) becomes correct once #110 + mip quality are
good enough that the box-mip/Lanczos gap is imperceptible — decided by the Phase-D A/B/X harness.

## 4. Load-bearing invariants (get these wrong → worse than today)

1. **Retain iff `content_gen` unchanged.** Geometry retains; content purges. Two separate paths.
2. **No hang:** after remap, either a retained hit is *successfully presented* (`presented_epoch =
   Some(epoch)`) or we deliberately fell through to decode (`None`). Never "retained but unpresented."
3. **`held` is the fallback, not the happy path** — only shown when no Original survives (Part A).
4. **Result-checked presents** — never stamp caught-up after `present_slot(false)`.
5. **Original-satisfied ≠ blurry** — `sharpen_now`/`tick_pie` must not fire on an Original-satisfied
   display, or the pie spins over a sharp frame.
6. **VRAM:** mips are shipped but mip-inclusive VRAM accounting is not (~4/3 undercount). Retaining
   Originals longer makes that undercount more consequential — bound `full_res_radius` × the (fixed)
   allocation accounting before widening the radius.

## 5. Test matrix (pure-core where possible)

- `compact_to`: survivors land at expected `to`; remaps correct; over-capacity survivors dropped in
  priority order (extend the existing `drop_fit_slots_keeps_originals…`).
- Geometry invalidation with a resident current Original: **no** decode job for the current item,
  `target_caught_up()` true, `presented_epoch == Some(epoch)`, ring `displayed` pin restored.
- Current Original **not** resident → fall-through: `presented_epoch` stays `None`, a Fit `Want` is
  queued, `held` fallback engaged.
- **Nav-after-toggle** (the owner's case): advance to a neighbour whose Fit was dropped but Original
  retained → presents the Original (no preview), schedules a background Fit refine, no pie.
- `content_gen` bump still purges Originals (existing content-path test green); undo-rotation of a
  *navigated-away* item purges its Original.
- Renderer-held fallback; same-index content replacement; compare-pin retention; present failure;
  resize-during-pending-navigation; silent background-Fit completion (no preview-over-Original, no pie).

## 6. Phasing

- **6a** — `remap_ring` (+ `pb-core` dep, held fallback, validation) + split `invalidate_geometry` /
  `invalidate_content` + the `full_res_window` keep-order. Ring/renderer stay in sync; current photo
  still instant via the retained slot (reconcile the `resize_hold` path).
- **6b** — the display-selection rule (Part C) + scheduler agreement + Part D re-present. **This is the
  phase that fixes the owner's advance-after-toggle complaint.**
- **6c** — Part E refine, wired to #110 when it lands.
