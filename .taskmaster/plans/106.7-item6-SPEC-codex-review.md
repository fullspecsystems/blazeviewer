# Codex review of `106.7-item6-retain-remap-SPEC-DRAFT.md`

> Reviewer: Codex (GPT-5 class), 2026-07-18, against the **current Windows tree** (Rachel drafted
> on an older macOS checkout, so her line anchors had drifted). Verdict cross-checked by Claude
> Code. This is a design review — not applied. Anchors below are current-tree.

## Verdict

**Approve the architecture; reject this execution draft until it's hardened.** The retain → compact
→ GPU-remap kernel is right, and all three residency primitives exist and are unused outside tests:
`SlotRemap` (`ring.rs:109`), `drop_fit_slots` (`ring.rs:218`), `compact_to` (`ring.rs:260`). But the
draft has **three release-blocking (P0) regressions** as written.

## P0 regressions (must fix before implementing)

1. **Content-change would wrongly retain stale Originals.** `invalidate_content` bumps `content_gen`
   then calls `invalidate_geometry` (`app_core_impl.rs:6941`). If geometry-invalidation starts
   retaining Originals, content-invalidation retains them too — and neither `drop_fit_slots`,
   `compact_to`, nor `original_slot` checks `content_gen`. That is exactly the "wrong deck item N"
   failure. ⇒ Split into **separate geometry-retain and content-purge paths**; `invalidate_content`
   needs an explicit total purge, not "increment + call the retaining path."
2. **`remap_ring` loses today's `held` fallback.** It drops every non-remapped slot without first
   moving the displayed slot into `held`. When no current Original survives, Rachel's "existing
   held+pie fallback" no longer exists (today `reserve_ring` explicitly preserves it, `gpu.rs:3151`).
   ⇒ On a miss, move the old presented slot into `held` + sync `img_w/img_h`, as `reserve_ring` does.
3. **`presented_epoch` does NOT actually prevent Fit re-decodes.** `request_prefetch` never consults
   `target_caught_up()`; in Fit mode `drop_fit_slots` removes every Fit, `display_slot` accepts only
   `RepKind::Fit` (`:5669`), the job loop schedules missing Fits (`:5535`), and `work_pending` treats
   a missing display-rep slot as outstanding (`:321`). So the retained-Original present would still
   trigger a full Fit-ring refill. ⇒ The "no redundant decode" claim needs real scheduler changes,
   not just an epoch stamp.

## Other required corrections

- **Anti-hang re-present must be result-checked.** Rachel's `self.item` doesn't exist — it's
  `target_item`. `target_caught_up()` only holds when `target_item == displayed_item` (`:6542`).
  Must check the `present_slot()` bool, only mark caught-up on a successful rebind, restore the ring
  `displayed` pin (`ring.set_displayed`, `:6452`), update `displayed_item`/metadata, and leave the
  target pending on a miss. Blindly stamping the epoch after `present_slot(false)` permanently marks
  the wrong frame resolved. (No `drain_results` thread race — both serial on the event loop — so it's
  not the reverted cff70ca0 failure; the danger is *logical* false-success. Align with the tracked
  `present_item` result-propagation follow-up rather than adding a second unchecked present path.)
- **`remap_ring` hardening:** validate `to < new_capacity` in *release* (not just `debug_assert!`),
  reject duplicate `to`s; the "old holds only Fits" comment is wrong (it can hold compaction-dropped
  Originals too); prefer a status-returning contract over a void method. `pb-render` does **not**
  currently depend on `pb-core` — add the workspace dep (no cycle; `SlotRemap` is re-exported).
- **Keep order** should reuse `full_res_window()` (current → compare-pin → neighbours, `:5765`), not a
  hand-rolled order that omits the compare pin.
- **Pending Originals:** `drop_fit_slots` preserves them but `compact_to` gathers only *resident*
  ones and silently discards pending; the decode pool also cancels all jobs on an epoch change.
  State the contract (cancel + re-request) explicitly.
- **Integrate with `resize_hold`** (`app_core.rs:482`, `resize()` at `:1358`) — resize *already*
  presents the retained Original and arms `resize_hold`. The draft must replace/integrate that flow,
  not add a second re-present mechanism.
- **Pre-existing caller hole to fix first:** undo-rotation only `invalidate_content()`s when the
  photo is displayed (`:681`/`:705`); a navigated-away neighbour Original can retain the old
  orientation once Originals live longer. Invariant: *every* pixel-affecting edit bumps `content_gen`
  and purges the affected residency regardless of what's displayed.

## The (a)-vs-(b) fork

Recommend **(b)** (present retained Original now + refine), **but not as Rachel specifies it** — and
her premise is stale: Original uploads **already** build mip chains + trilinear (`gpu.rs:1440`).
However box-mip trilinear still differs from Lanczos on grass/fabric (owner-tested) and source-ICC
images aren't mipped, so Original-only isn't a universal final-quality path yet. Make (b) a
**current-item-only, silent refinement** with an explicit "Fit refinement complete" present — do NOT
present its embedded preview over the retained Original, and do NOT show a pie over an already-sharp
frame (`tick_pie` watches `sharpen_now()`, `:9548`). The better endpoint is task #110's GPU-derived
exact-size Lanczos/Kaiser from the retained texture (no SMB read, no CPU decode).

## Interaction with the stuck-preview desync (bug 1)

**Item-6 does NOT fix bug 1 — treat as orthogonal.** A geometry invalidation may *incidentally*
unstick an occurrence (it drops the stranded 256px Fit), and re-presenting an Original can *mask* the
blurry Fit — but option (b) runs the same decode/classification path and can **recreate** the tiny
`is_preview=false` Fit. Codex's added insight: *if a preview Fit lands while the Original is actually
displayed, `preview_resident` can make `sharpen_now()`/the pie claim the visible image is blurry when
it isn't — a separate "currently-presented representation/refinement" state is needed.* That points at
the same `preview_resident` conflation we're fixing for bug 1.

## Bottom line

Approve the architecture; the execution draft needs: the content-purge split, the `held` fallback,
real display-selection/scheduler semantics (not just an epoch stamp), `resize_hold` integration, and
a broader test matrix (renderer-held fallback, same-index content replacement, compare-pin retention,
present failure, resize-during-pending-navigation, silent background-Fit completion — not only ring
compaction). Then it's implementable.
