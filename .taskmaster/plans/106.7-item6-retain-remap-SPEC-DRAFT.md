# 106.7 Item 6 — Retain & Remap the Ring on Geometry Change (Implementation Spec)

> **STATUS: DRAFT — 2026-07-18. Author: Rachel. Expect iteration.**
> This is a scoped execution spec for one piece of Task 106.7: making a geometry
> change (resize / fullscreen toggle / Fit↔1:1) *retain* the already-decoded
> full-resolution `Original` textures instead of throwing the whole ring away and
> re-decoding. It operationalizes **§6 (retain/remap API)** and its load-bearing
> companion **§3 (explicit re-present)** from
> [`106-performance-archive-zoom.md`](106-performance-archive-zoom.md). Read that
> plan first; this doc assumes it.
>
> **Not in scope** (deliberately): Tier-2 mipmaps, the downscale-filter A/B/X
> harness (Phase D), and the Windows DWM present-freeze. Those are separate.

---

## The bug this fixes (one paragraph)

Pressing **f** (fullscreen), dragging a resize, or toggling Fit↔1:1 shows a
blurry low-res frame + a spinning pie + a ~1s wait before the sharp image lands —
**every time, on the same image, with zero cache benefit.** Root cause: Blaze
decodes-to-fit (the on-screen texture is a CPU-Lanczos downscale sized to the
exact viewport, keyed by a geometry epoch), and on any geometry change
`invalidate_geometry` **news up an empty ring** and discards every resident
texture — including the parked full-resolution `Original` copies we already
decoded for `current ± full_res_radius`. Those Originals are geometry-*independent*
and would let us re-fit the current image on the GPU instantly, but we drop them.
So the current image gets re-read from disk and re-Lanczos'd from scratch.

## Verified current state (ground truth, 2026-07-18)

What's **already built and tested** (do not re-derive):

- `ResidentRing::drop_fit_slots() -> Vec<(usize, usize)>` — `pb-core/src/ring.rs:218`.
  Frees all `Fit` slots (stale at the new epoch), keeps resident `Original`s, returns
  the surviving `(item, old_slot)` pairs. Clears the `displayed` pin. **Tested:**
  `drop_fit_slots_keeps_originals_across_a_geometry_change` (`ring.rs:764`).
- `ResidentRing::compact_to(new_capacity, keep: &[usize]) -> Vec<SlotRemap>` —
  `ring.rs:260`. Compacts survivors into a (possibly smaller) ring in priority order,
  drops occupants that no longer fit / exceed budget, returns old→new `SlotRemap`s.
  Must be called *after* `drop_fit_slots`.
- `SlotRemap { from: usize, to: usize, item: usize }` — `ring.rs:109`.
- The **parked full-res prefetch tier** already decodes and holds Originals for
  `current ± full_res_radius` (`app_core_impl.rs:5280`; `full_res_radius()` at `:5455`,
  default 1, clamp `FULL_RES_RADIUS_MAX`). So in steady state the current item has
  **both** a displayed `Fit` slot and a resident `Original` slot.
- `content_gen` is already separate from the geometry `epoch` (`app_core.rs:441`), so
  a resize bumps `epoch` only and an Original conceptually survives it; a *content*
  change bumps `content_gen` and must purge Originals.
- §3 hooks exist: `target_caught_up()` (`app_core_impl.rs:6218`), `try_present_target()`
  (`:6233`), and the epoch stamp `presented_epoch = Some(self.epoch)` (`:6195`).

What's **missing** (the entire gap):

1. `invalidate_geometry()` (`app_core_impl.rs:6553`) **does not call** `drop_fit_slots`
   / `compact_to`. It does `self.ring = ResidentRing::new_with_budget(cap, …)` — a
   full discard — then `renderer.reserve_ring(cap, …)`.
2. The `Renderer` trait (`pb-render/src/lib.rs:118`) has **no remap method**. It has
   `reserve_ring` (`:227`, empties the GPU slot vector, stashes the presented slot in
   `held`) and `present_slot` (`:245`). There is no way to tell the renderer "keep these
   textures, move them to these new indices."
3. Nothing **explicitly re-presents** the retained Original at the new epoch, so even
   if we retained it, §3's anti-hang requirement is unmet.

**One-sentence gap:** the residency-side primitives are done; the renderer-side remap
API and the app-side wiring + re-present are not.

## The change

### Part A — new `Renderer` trait method: `remap_ring`

Add to the `Renderer` trait (`pb-render/src/lib.rs`, next to `reserve_ring`):

```rust
/// Rebuild the GPU slot vector to `new_capacity`, RELOCATING retained textures
/// per `remaps` (old slot -> new slot) instead of dropping them. Each surviving
/// `RingSlot` (its wgpu texture/view/bindgroup) moves from `remaps[i].from` in the
/// current ring to `remaps[i].to` in the new ring; every other slot is freed. Unlike
/// `reserve_ring`, this does NOT stash anything into `held` — the caller re-presents
/// the retained current-item slot directly (see §3). `present_idx` is cleared; the
/// caller sets it via `present_slot`.
fn remap_ring(&mut self, new_capacity: usize, remaps: &[SlotRemap]);
```

`gpu.rs` impl (model it on `reserve_ring` at `gpu.rs:2870`, but *move* rather than
*empty*):

```rust
fn remap_ring(&mut self, new_capacity: usize, remaps: &[pb_core::ring::SlotRemap]) {
    let mut old = std::mem::take(&mut self.ring);
    let mut next: Vec<Option<RingSlot>> = (0..new_capacity).map(|_| None).collect();
    for r in remaps {
        // r.from indexes the OLD ring; take the texture and place it at r.to.
        if let Some(slot) = old.get_mut(r.from).and_then(Option::take) {
            debug_assert!(r.to < new_capacity);
            next[r.to] = Some(slot);
        }
    }
    // `old` now holds only non-retained (Fit) slots; dropping it frees their textures.
    self.ring = next;
    self.present_idx = None;
    // NOTE: do NOT touch `self.held` here. If a prior held frame exists it stays as a
    // last-resort; but the happy path presents a retained Original immediately after.
}
```

`SlotRemap` needs to be importable from `pb-render` — it already lives in
`pb-core::ring`, which `pb-render` can depend on (verify the dep edge; add if absent).

> **Implementer, verify:** the exact `RingSlot` field set and whether `Option::take`
> on `self.ring[from]` cleanly transfers texture ownership (it should — the slot owns
> its wgpu resources). Confirm no other field (`img_w`/`img_h`, `reuse`, `scene_kind`)
> needs syncing on a remap the way `reserve_ring` syncs `img_w/img_h` for `held`.

### Part B — rewrite `invalidate_geometry` to retain

Replace the discard in `app_core_impl.rs:6553`. Sketch:

```rust
pub fn invalidate_geometry(&mut self) {
    self.epoch = self.epoch.wrapping_add(1);

    // 1. Free the stale Fit slots; keep resident Originals.
    let _kept = self.ring.drop_fit_slots();

    // 2. Priority order for the (possibly smaller) new ring: current first, then
    //    outward by full_res_radius — the same window the prefetch tier fills.
    let keep = self.retain_priority_order(); // current, current±1, ... (see note)

    // 3. Compute new capacity for the new geometry and compact survivors into it.
    let cap = ring_capacity(self.slot_bytes_estimate());
    let remaps = self.ring.compact_to(cap, &keep);

    // 4. Tell the renderer to relocate the retained textures (not empty the ring).
    if let Some(a) = self.renderer.as_mut() {
        a.remap_ring(cap, &remaps);
    }

    let (ahead, behind) = window_for_capacity(cap);
    self.ahead = ahead;
    self.behind = behind;
    self.pending_uploads.clear();

    // 5. §3: explicitly re-present the retained current Original, or fall through.
    self.present_retained_or_fall_through();
}
```

> **Implementer, verify:** `ring_capacity`/`slot_bytes_estimate` currently size for the
> *Fit* slot budget. A Fit→Fit resize (windowed→fullscreen — JD's actual bug) keeps the
> rep Fit, so capacity should be roughly stable and the Originals remap in place. A
> Fit→Original toggle changes slot size and *shrinks* capacity — that's exactly what
> `compact_to` is built for. Confirm `slot_bytes_estimate` reflects the rep we're
> landing in, not the one we're leaving.

`retain_priority_order()` is a small helper: `[current, current+1, current-1,
current+2, current-2, …]` out to `full_res_radius()`, clamped to the playlist. Index 0
is highest priority (never dropped by `compact_to`).

### Part C — §3: explicit re-present (the anti-hang invariant)

`present_retained_or_fall_through()` is the load-bearing bit. Per plan §3 (lines
124–134): a retained hit that isn't *explicitly presented* leaves the app showing the
old frame forever, because `request_prefetch` will skip the decode (the Original is
resident) and nothing else draws.

```rust
fn present_retained_or_fall_through(&mut self) {
    // Is the CURRENT item's Original resident in the remapped ring?
    if let Some(slot) = self.ring.original_slot(self.item) {   // ring.rs:174
        if let Some(a) = self.renderer.as_mut() {
            a.present_slot(slot);          // draw the retained Original, GPU-refit
        }
        self.presented_epoch = Some(self.epoch);  // -> target_caught_up() == true
        // => request_prefetch schedules NO re-decode for the current item.
        self.draw();
    }
    // else: no retained Original (e.g. we navigated <~400ms ago and its decode
    // hasn't landed). Leave presented_epoch = None so the existing held+pie path
    // runs and the async Fit re-decode fills in — today's behavior, for this one
    // toggle only. Graceful degradation, not a regression.
}
```

## Load-bearing invariants (get these wrong and it's worse than today)

1. **content_gen guard — the "wrong deck item N" landmine.** Retain is valid ONLY for a
   *geometry* invalidation. `invalidate_geometry` bumps `epoch` and NOT `content_gen`, so
   this is safe here. But the **content-change path** (the sibling of this function,
   `app_core_impl.rs:6570+`) must still fully purge Originals — a retained Original whose
   index now names different pixels is "the sharpest bug in the Codex review" (plan). Do
   **not** refactor the two paths into one that retains unconditionally. State this as an
   explicit invariant in the code comment: *retain iff `content_gen` unchanged.*

2. **No hang.** After remap, either `presented_epoch == Some(epoch)` (we presented a
   retained hit) **or** we deliberately left it `None` to fall through to decode. Never a
   third state where the ring holds the Original but nothing presents it. The plan's test
   for this: "a geometry toggle on a retained Original issues **no decode** AND becomes
   `target_caught_up`" (plan line 224).

3. **`held` is now the fallback, not the happy path.** Today `held` (the blurry upscaled
   old Fit texture) is *always* shown on resize. After this change it should only appear
   when there's no retained Original (case C's `else`). Don't delete `held` — it's the
   correct degradation — just stop routing the common case through it.

## Open design fork (needs a JD/Rachel decision — flagged, not decided)

When we present the retained **Original** in **Fit** mode, the GPU downscales full-res →
viewport through the **Linear** sampler (`gpu.rs:875`). A big downscale + bilinear =
*sharp but mildly aliased* on fine detail (grass, text, brick) — not blurry like today,
but not identical to the CPU-Lanczos Fit texture either. Two options:

- **(a) Present Original-refit and stop.** Zero decode, ~0ms, but the interim *is* the
  final and may shimmer on high-frequency detail. Matches plan §3's "only decode when
  there's no retained hit" literally.
- **(b) Present Original-refit immediately, AND still schedule the background Lanczos Fit
  decode** to replace it a beat later with the pristine version. Kills the blur+pie
  *instantly*, then quietly perfects. Costs one background decode (invisible; you're
  already looking at a crisp frame).

**Rachel's recommendation: (b) as the default.** It's strictly better UX and the extra
decode is off the critical path. **(a)** becomes the right answer once **Tier-2 mipmaps**
land (trilinear on a mipmapped Original = high-quality downscale, no re-decode ever) — at
which point the A/B/X harness (Phase D) is the tool that decides *which* mip filter. So:
ship (b) now, revisit (a) when mipmaps + the harness exist. This is the piece I most
expect us to iterate on.

  `compact_to` assertion: survivors land at expected `to` slots, remaps are correct,
  over-capacity survivors dropped in priority order.
- New app-core test (plan line 224): after `invalidate_geometry` with a resident current
  Original, assert (1) the decode pool receives **no** job for the current item, (2)
  `target_caught_up()` is true, (3) `presented_epoch == Some(epoch)`.
- New: current item's Original **not** resident → assert fall-through (`presented_epoch`
  stays `None`, a Fit `Want` is queued). Guards the degradation path.
- `content_gen` bump still purges Originals (existing content-path test must stay green).
- `PB_PERF` manual: resize→on-screen for a dwelt-on image is **~0ms rebind** vs ~400ms
  today (plan line 233). This is the number that proves it to the eye.
