## The decision (rev2, unchanged)

macOS uses **`AVPlayer` + `AVPlayerLayer` as the single, authoritative media pipeline** — system
decode, color, HDR, audio, timing, buffering, seeking. The cross-platform Rust `VideoSession`
and the decode *producers* remain the **Windows/Linux** engine and are **not run on macOS**. What
stays shared is **product semantics**, not decoded frames.

**Why justified** (the finding that flipped it): on macOS the shell root is `MetalCanvas` (a
`CAMetalLayer` wgpu draws into) with every overlay a SwiftUI `.overlay` above it
(`PhotoBlazeMacApp.swift:142–293`). SwiftUI is the compositor; wgpu is only the *still* renderer.
Video never needed to traverse wgpu to composite with the chrome, and AVPlayer does fit/rotation/
color/HDR/A-V-sync/seeking natively and generally better (real HDR/Dolby Vision; correct
mirrored/non-quadrant rotation; ProRes; power-efficient media-engine decode; far less unsafe
`objc_msgSend`). This extends the project's "best tool per platform behind a seam" philosophy
(WIC/ImageIO/FFmpeg for decode) from decode to the whole playback engine on the one platform with
a first-class native player.

**Performance/HDR wording (finding #11):** we do **not** assert an API-level "hardware decoder
selected" invariant (AVPlayer exposes no such query). The product contract is: *AVFoundation-managed
native playback meeting the measured performance, power, color, and HDR gates.* Phase 0 records
Mac/SoC/macOS/codec-profile/bit-depth; media-engine use is expected system behavior, not an
asserted invariant. "HDR/Dolby Vision correct" is scoped to a supported file profile + an eligible
Mac/display + a verified EDR layer topology.

## Goal

A video in a macOS library behaves like on Windows: instant **poster + play badge**, `P` plays
with sound, horizontal-pan actions seek, and the info line (`i`) grows an **interactive playback
row** — `⏵ 0:42 ▰▰▰▱▱ 9:01` — whose bar is a click/drag scrubber. Playback is native, HDR-correct,
and meets the perf gates. The native player is more capable than tier-2's "coarse by design"
charter needs; that headroom is free and leaves an easy path to subtitles/PiP/AirPlay later, none
in scope now.

**Non-goals (this task):** subtitles, chapter UI, audio-track selection, remember-position,
PiP/AirPlay, MKV/WebM (no AVFoundation demuxer → placeholder + graceful error). **Continuous** frame
extraction into Rust/wgpu is explicitly rejected (finding #5 / D2).

## Architecture

### Layer topology — a Phase-0A *decision to prove*, not an assumption (finding #1)

`MetalCanvasNSView` is itself a layer-backed view whose backing layer **is** the `CAMetalLayer`
(`MetalCanvas.swift:15`, `:337`); there is no generic container today. Phase 0A must choose and
prove one topology:

- **First choice (least invasive):** add `AVPlayerLayer` as a **sublayer of the existing
  `CAMetalLayer`**.
- **Escalation:** refactor to a generic root layer holding separate `CAMetalLayer` + `AVPlayerLayer`
  children.

The spike must verify, for the chosen topology:
- SwiftUI overlays remain above the player layer.
- Canvas pointer/scroll/pinch/context-menu/drag-drop handling stays owned by `MetalCanvasNSView`.
- Metal resize + EDR reconfiguration don't disturb the player sublayer.
- The player layer's bounds/scale track live resize, fullscreen transitions, and display changes.
- Detach removes the player layer + **all** observations before the backing Metal layer dies.

Until proven, the doc says **sublayer of the `CAMetalLayer` (pending Phase 0A)**, not "sibling."

### Presentation lifecycle + startup gate (finding #2)

The player layer's visibility follows the media lifecycle — it is **not** hidden at EOS (that
would reveal the poster and break the Windows "park the true last frame" parity):

| Phase | Layer | Notes |
|---|---|---|
| Opening | attached, **hidden**, paused | poster (wgpu) visible |
| First displayable frame ready | **revealed atomically** | the only reveal point |
| Playing / Paused / Buffering / Seeking | visible | — |
| Ended | visible, **parks the true last frame** | never re-show the poster |
| Replay (`P` at EOS) | visible | seek→0, resume when the seek lands |
| Navigate / Stop / Failure | **hidden + torn down** | reveals the current/new poster |

**Audio gate:** open **paused**, preroll if useful, wait for the first displayable frame, reveal
the layer, *then* begin playback — so audio never leads the picture over a still poster.
Acceptance: no audio-before-picture; EOS retains the last frame; `P` at EOS replays from 0; a
failed open returns to the poster + surfaces one useful error.

### The shared semantic contract (the only cross-platform boundary)

Every command/callback carries a **`session_id`**; seeks carry a **generation** token so a
superseded seek's async result can never affect the current session. AVPlayer is the single timing
authority — the core runs no competing state machine on Mac.

**Command model (finding #8 — event-oriented, no core position mirror):**
```
Core → Swift (CoreEffect commands, session_id on all):
    PlayVideo { session_id, path, muted }
    PauseVideo { session_id }            ResumeVideo { session_id }
    SeekVideoBy { session_id, generation, delta_ms }      // core owns ±2s / Shift ±10s semantics
    SeekVideoFraction { session_id, generation, fraction }// Swift resolves vs AVPlayer time
    StepVideo { session_id, forward }
    SetVideoMuted { session_id, muted }
    StopVideo { session_id }
    CaptureNativeVideoFrame { session_id, item, purpose, request_id }   // finding #5
```
Because Swift resolves seeks against AVPlayer's current/latest-desired time, **the core never needs
an AVPlayer position mirror** — killing the "second clock" rev2 had. The info row reads AVPlayer
directly (below), so **no periodic Swift→Core progress is required**, and `CADisplayLink` can stay
paused during native playback (the AVPlayer observer wakes only the SwiftUI state that changed).

**Typed callbacks (finding #7 — not one catch-all):**
```
Swift → Core (typed FFI entry points, session/generation-validated):
    native_video_opened { session_id, duration, has_audio, width, height }
    native_video_state_changed { session_id, state }   // Opening|Buffering|Playing|Paused|Ended|Failed
    native_video_seek_completed { session_id, generation, finished }  // finished=false ⇒ interrupted
    native_video_failed { session_id, error }
    native_video_ended { session_id }
    native_video_frame_ready { session_id, item, purpose, request_id, pixels, w, h, fmt }
```
Rules: `StateChanged` does not duplicate `Ended`/`Failed`; a pending seek suppresses progress/state
churn until the latest seek completes or is interrupted (never publish the old time under the new
generation); **every** KVO/notification/preroll/seek/readiness/snapshot callback captures + validates
the session id; every observer/time-observer token is removed on stop and on replacement.

### Core-side changes (`pb-app-core`) — lock the facade first (finding #3)

`AppCore::video` is `Option<video_session::ActiveVideo>` today (`app_core.rs:505`), and **45**
`self.video`/`.session` sites reach into it across work-pending/slideshow/deletion/play-pause/seek/
step/progress/tests. Scattering `#[cfg]` branches through all of them recreates the divergence the
seam is meant to contain. **Resolution: a common facade, landed as its own step before the Mac
work.**

```rust
enum ActiveVideoBackend {
    Session(SessionVideo),      // Windows/Linux — wraps today's VideoSession + ActiveVideo fields
    Native(NativeVideoProxy),   // macOS — pure passive mirror of AVPlayer's authoritative state
}
// common helpers used by cross-cutting policy:
impl ActiveVideoBackend { fn item(); fn state(); fn is_active(); fn is_playing();
                          fn duration(); fn desired_position(); fn session_id(); }
```
Common policy (slideshow suspend, deletion, play-hint, mute availability, work-pending) uses the
facade; genuinely platform-specific operations `match` the variant. `NativeVideoProxy` holds
`{ item, session_id, seek_generation, state, duration, muted }` — **no position field** (finding
#8; timing is AVPlayer's). Updated by the typed callbacks (session/generation-gated), read by the
facade helpers. Pure ⇒ unit-tested on fake callbacks, no AVFoundation.

The macOS arms: `start_video_session` (`app_core_impl.rs:5828`) emits `PlayVideo` + sets a
`Native` proxy (no thread/producer/session); `video_seek*`/`video_frame_step`/`video_play_pause`/
`stop_video` emit the matching command (bumping generation on seeks); `poll_video` is a no-op on
Mac; the new `native_video_*` handle methods apply callbacks to the proxy.

### Native view-transform mirroring (finding #4 — not just fit + rotation)

Windows video frames traverse the same renderer as stills, inheriting manual rotation, zoom, pan,
scale-mode, content/top inset, and fullscreen/resize geometry. `videoGravity = .resizeAspect`
covers only default Fit. Critically, the **contextual arrow routing** depends on
`pannable_horizontally()` (pan wins under horizontal overflow, else arrows seek); if the player
layer doesn't mirror the core view transform, the input decision and the visible image disagree.

**Approach (preferred, less new vocabulary):** on the existing render-request effect
(`RequestRender`/redraw — every view mutation already triggers one), let Swift **pull the core's
current `ViewTransform`** and apply it to the player container (layer `transform`/`frame`) before
wgpu renders the poster/stills. A dedicated `SetNativeVideoView { … }` command is the fallback if
the pull proves racy. `rotate()` currently updates only the wgpu renderer (`app_core_impl.rs:4499`);
it must also drive the player-layer transform on Mac.

Phase 0A + acceptance cover: Fit/Fill/Original as applicable; zoom + pan; horizontal
pan-vs-seek routing agreement; manual quarter-turn rotation while playing **and** paused; rotated
content refit without crop; toolbar/content top inset; moving between displays + backing-scale
changes.

### Poster + async metadata probe stay in Rust (findings #10)

Posters integrate with the Rust decode pool / prefetch / cache-residency (engine `decode_item` →
`decode_video_poster` → `DecodedImage` → wgpu still), so poster + probe remain Rust:

- New `pb-decode/src/av_poster.rs` (`#[cfg(target_os = "macos")]`): `decode_video_poster(path, fit,
  cancel)` + `probe_video_stream(path) -> VideoStreamInfo`, reusing `livephoto.rs`'s `AVAssetReader`
  shims for a capped first-non-black walk (shared `poster_frame_bright_enough`/`POSTER_MAX_*`). A
  small bounded module, not a producer.
- Promote `VideoStreamInfo` (+ `display_dims()`) from `mf_poster.rs:55` to ungated `video.rs`; wire
  `lib.rs` re-exports mirroring the Windows lines.
- **Do not repeat the sync-probe-on-main-actor trap:** `probe_video_stream` is today called
  synchronously inside `ensure_exif_cached` (`app_core_impl.rs:5640`, a main-loop path). On Mac,
  either run a **cancellable background probe cached by item**, or return metadata as a **side
  result of poster generation** (the decode pool already runs off-thread). The inspector shows
  stable pending values until it arrives. No new synchronous AVAsset metadata path on the main actor.
- Widen the poster cfg gate (`engine.rs:270`) to `#[cfg(any(windows, target_os = "macos"))]`;
  route the probe through the async path rather than widening the `:5640` sync gate as-is.

### Displayed-frame capture for Copy / OCR / Describe / Compare (finding #5)

The existing actions decode from the source, so a video yields the poster: `copy_image` (:4546),
OCR `scan_job` (:4710), Describe `describe_job` (:4869) all decode via the source; they must accept
**native pixels** instead. Contract:

- **Preferred API order:** (1) `AVPlayerLayer.copyDisplayedPixelBuffer()` — returns exactly what the
  user sees; (2) fall back to a **permanently attached but only-on-demand-pulled**
  `AVPlayerItemVideoOutput`; (3) do **not** attach the output only at the instant of the command
  unless the spike proves it immediately returns the current frame.
- Flow: `CaptureNativeVideoFrame{ session_id, item, purpose, request_id }` → `native_video_frame_ready{
  …pixels }`; Rust routes the returned frame into **pixel-based** versions of the clipboard/OCR/
  describe jobs. `session_id`/`item`/`request_id` reject a frame captured before navigation.
- Purposes: Copy, OCR, Describe, **Compare** (pin/freeze current frame — no hidden continuing
  playback).
- Snapshot handling: bake manual rotation into the image; define HDR/P3→clipboard conversion
  (clipboard is RGBA8); no continuous polling / no retained frame history; support paused + EOS
  snapshots; a graceful "frame unavailable" result.

### Info line — interactive, accessible (finding #6)

The current info line is `.allowsHitTesting(false)` (`PhotoBlazeMacApp.swift:249`), so no control
can receive input. Required:

- Enable hit testing **only when a playback row is present**, and make **only the actual controls/
  bar** interactive — transparent padding must not swallow canvas pointer/scroll/drag input.
- **Cursor:** reuse the existing string-based `desiredCursor` path (`CoreModel` already maps
  `"pointer"`→`.pointingHand`) rather than `setPanelResizeCursor` (which gives `.resizeLeftRight`,
  `CoreModel:1917`); add a small generic overlay-cursor-claim so the scrubber can hold
  `.pointingHand` against the canvas's `cursorUpdate` re-assert.
- **Local drag state:** the knob follows the pointer during a drag; periodic AVPlayer observations
  must not yank it away. Reset the local state **only** when the matching seek generation lands or
  fails (`finished` from `native_video_seek_completed`).
- **Seek throttle:** by **time** (≤10–15 seeks/s) *and* distance (≥1 px), plus an **unconditional
  final seek on release** at the last requested generation. (1 px alone can still fire hundreds of
  seeks over a long drag.)
- **Accessibility:** VoiceOver label, play/pause traits, current/total value, an adjustable
  scrubber action.
- The row is driven by AVPlayer observations in Swift (time observer + status KVO + item duration);
  actions (play/pause button, scrub) dispatch through the core so they match `P`/menu.

**Pointer-reveal (owner ask 2026-07-12).** For a video the controls should appear when the pointer
moves near the **bottom of the screen** — a discoverable affordance so a user need not know the `i`
hotkey. Design: while a video session is engaged, a pointer inside a bottom hot-zone (≈ the bottom
15% / a fixed band) reveals the playback row (fade in via `Layout.chromeFade`); it auto-hides after
a short idle once the pointer leaves the zone and no scrub/hover is active. This is **independent of
the `i` toggle** (which still force-shows the full info line) and applies only to video items — a
still doesn't get a bottom-reveal. Interacts with cursor auto-hide (below): pointer motion that
reveals the controls also un-hides the cursor. Implement Swift-side (the shell owns the pointer +
the row's visibility), gated on the core's "displayed item is a live video" signal.

### Cursor auto-hide (task #68, folded in 2026-07-12) — cross-platform

Owner ask (2026-07-09, #68): hide the mouse pointer when idle (and in the borderless speed mode),
as an **option**, on every platform — doubly relevant now that PhotoBlaze plays video and runs
slideshows. Half the plumbing exists but nothing hides today: `CursorKind::Hidden` is defined
(`contract.rs:80`) but **no core code emits `SetCursor(Hidden)`** (`hover_cursor` only emits
Grab/Grabbing/Pointer/Default), the winit shell **stubs** it (`main.rs:3361` maps Hidden → Default),
and the macOS shell honors it (`CoreModel.swift` `setHiddenUntilMouseMoves(true)`) but it's dead
code since the core never sends it.

Work (a self-contained cross-platform feature):
- **Core idle policy:** track last pointer-move time (the core already sees pointer events); after
  an idle threshold emit `SetCursor(Hidden)`, and restore on the next pointer move. Threshold ~2–3 s
  (or immediate in the fullscreen speed mode). A new setting `cursor_autohide` gates it. Pure/
  testable in `pb-core`/`pb-app-core` (injected time, like the slideshow timer).
- **winit shell (Windows + Linux):** truly hide via `Window::set_cursor_visible(false)` (works on
  Windows + X11; Wayland is compositor-mediated → accept graceful degradation). Replace the
  Hidden → Default stub.
- **macOS shell:** the `setHiddenUntilMouseMoves` path already works once the core emits Hidden;
  confirm it fires + un-hides on move.
- **Video interplay:** while a video plays and the pointer is idle, hide the cursor **and** the
  playback controls together; any pointer motion restores both. Slideshow behaves the same.
- Acceptance: cursor hides after the idle threshold in windowed + speed mode on macOS + Windows
  (+ X11), restores on move, never hides while the pointer is over an interactive control, and is
  off when the setting is off. This closes **task #68** for macOS + Windows (+ X11) in one pass.

### Delete/teardown — no Windows locking assumptions (finding #12)

macOS doesn't require closing an open file before Trash/unlink. Order: (1) core invalidates the
native session + emits `StopVideo`; (2) Swift hides/detaches the layer + cancels observers/tasks;
(3) delete proceeds **without blocking the main actor**; (4) stale callbacks rejected by session id.
Test Trash + permanent delete while playing, but **add no wait unless measurement proves it needed**
— do not port the Windows retry machinery.

## Acceptance criteria — reportable gates (no "smooth"/"promptly"/"flat")

- P→first-picture and P→first-audio **p50/p95** recorded; **no audio before the first displayed
  frame**.
- No avoidable rebuffer over a 10-min corpus run.
- Poster↔video and video↔photo handoff **within one refresh**.
- Seek request→present **p50/p95**; **≤ chosen** live seek requests/s; the final scrub release
  always lands at the final requested generation.
- A/V sync error under threshold after startup + seek settling.
- RSS slope after warmup ≈ 0 over 10-min (opt-in 2-h).
- **Zero** native observer/player/output objects retained after navigation.
- Main-thread checker / profile confirms no synchronous asset/probe/frame-conversion on the main
  actor.
- **Hidden-video baseline:** no regression in still-photo keypress→photon.
- HDR/Dolby-Vision correct for a supported profile on an eligible display + verified EDR topology.
